# M4: graph replay and decode speed

**Status:** in progress (Nov 2026). **Compile unlock default** (`TENSCUDA_COMPILE=1`; `=0` eager)
(~36 tok/s SmolLM2 on `tens`, 32/32 vs eager). Learnings + next levers:
**[M4_LEARNINGS.md](M4_LEARNINGS.md)**.

**Prerequisite done:** `scripts/kv_diagnose.py` shows **8/8** parity for per-step sync vs **3/8**
for multi-forward lazy graphs (`results/kv_diagnose_SmolLM2-135M-Instruct.json`).

## Problem

Warm decode was host/trace-bound. On legacy `rock`, `trace_cost` split (~SmolLM2):

| Component | ~ms/step (`rock`) | ~ms/step (`tens`) |
|---|---|---|
| Python → lazy IR trace | 75–103 | ~23 |
| `torch_xla.sync` + execute | 163–178 | ~33 |

Host upgrade + pause modes + **compile unlock** moved SmolLM2 from ~3.6 → ~18 → ~23 → **~36 tok/s**.
Remaining gap to 3090 is mostly device execute + missing native kernels (E4), not “more Python tweaks.”

## Constraints (do not violate)

1. **One `torch_xla.sync()` between decode forwards** when using HF `StaticCache`.
2. **`torch.compile(backend="tt")`** must capture with torch-function modes **exited** and
   CPU-init StaticCache (`TENSCUDA_COMPILE=1` wiring in `generate.py`, Nov 23 unlock). Old
   PERF §5 “wrong from token 1” was modes-on capture / wrong cache setup.
3. **TensCUDA softmax/SDPA overrides** still required on the eager path (trace_cost `no_modes`
   diverges). Compile unlock currently runs modes-off for the compiled graph; greedy top-1
   matched baseline on 135M/1.1B overnight — keep validating vs CPU teacher.
