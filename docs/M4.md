# M4: graph replay and decode speed

**Status:** in progress (Nov 2026). **Prerequisite done:** `scripts/kv_diagnose.py` shows **8/8**
parity for per-step sync vs **3/8** for multi-forward lazy graphs (`results/kv_diagnose_SmolLM2-135M-Instruct.json`).

## Problem

Warm decode on one P150a is ~3–6 tok/s for sub-2B models. Measured split (`scripts/trace_cost.py`, §PERF):

| Component | ~ms/step (SmolLM2-135M) |
|---|---|
| Python → lazy IR trace | 75–103 |
| `torch_xla.sync` + execute | 163–178 |

Both must shrink for M4 to land; native kernels alone are insufficient.

## Constraints (do not violate)

1. **One `torch_xla.sync()` between decode forwards** when using HF `StaticCache`.
2. **`torch.compile(backend="tt")`** still wrong from token 1 on StaticCache (PERF §5).
3. **TensCUDA softmax/SDPA overrides** required for parity (trace_cost `no_modes` diverges at token 2).
