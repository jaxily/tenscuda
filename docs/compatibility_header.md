# Model compatibility matrix

Generated by `python scripts/matrix.py MODEL` (one row per model, raw data in `results/matrix/`);
`python scripts/matrix.py --render` rebuilds this file. Do not edit the table by hand.

Setup: one P150a, single card, host with 8 GB RAM. TT runs use the streaming loader
(`tenscuda.loader`), bf16 weights, HiFi4 math with fp32 accumulation, a fixed-shape greedy loop,
batch 1, the chat prompt "Explain in two sentences why the sky is blue." and 32 new tokens.

- **parity vs CPU**: greedy tokens matching the CPU reference before the first difference. The
  reference is a plain greedy loop in fp32 if the model fits in host RAM, else bf16.
- **works (near-tie)**: the first difference is at a step where the CPU's top-2 logits are within
  0.25 of each other, which is about one bf16 rounding step at typical logit magnitudes.
  That's a precision effect, not an adapter bug.
- **warm tok/s**: decode speed of generate calls 2-4 (mean, min-max), after compilation.
- **first run s**: the first generate call, including TT-MLIR compilation.
- **peak host RSS**: process VmHWM after loading weights, and at the end.
- **CPU tok/s**: the CPU reference's decode speed on the same host (4 threads), for scale.
